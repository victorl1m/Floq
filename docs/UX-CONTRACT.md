## State and feedback

- Initial bootstrap, refresh, and mutations must be perceivable without hiding usable content or changing primary control dimensions.
- Disabled and busy controls remain named; async failures retain entered values and use the shared toast or inline error owner.
- Empty states should explain the missing content and provide the next permitted action.
- Respect both `prefers-reduced-motion` and the device-local Floq reduced-motion preference. Neither setting changes product behavior.
- The opt-in primary-action shimmer is decorative, stays out of the label/icon layer, and stops for disabled or busy actions, reduced motion, forced colors, and the solid material preference.
- Large dialogs, canvas cards, composers, and sidebars use static translucent fills and highlights. The expanded terminal body stays opaque.
- When native Mica/Acrylic/vibrancy is active, tint the canvas plane, canvas floating controls (branch switcher), editable canvas fields, and right-sidebar pane with theme-matched translucent fills; keep canvas cards, sidebar controls, and terminal content opaque. Solid material, OS reduced-transparency, and forced-colors must restore opaque fills. The canvas toolbar lives in the titlebar and inherits the titlebar chrome.
- Floating menus and ordinary dialogs may use bounded standard CSS backdrop blur (10px for menus, 8px for dialogs) to separate text from content underneath. Keep the full-screen scrim unblurred and exclude the expanded terminal shell; the terminal toolbar may remain visually distinct while terminal output stays opaque. `solid`, `system` with reduced transparency, unsupported browsers, and forced-colors use opaque/no-blur fallbacks.
- Sonner toasts use a bounded CSS blur with native material enabled, and use opaque surfaces for Solid, OS reduced-transparency, unsupported-browser, and forced-colors fallbacks. Position the single toast stack at the top center, below the native titlebar and inside the mobile safe area. Preserve Sonner's live-region, action, dismissal, and timeout behavior; titles and descriptions wrap instead of truncating recovery details.
- Do not store credentials in new UI preferences or local composer state.

## Organization switch

- Organizations partition the signed-in user's own projects; there is always a Personal organization, listed first and labelled "Personal" in both organization lists (switcher and account menu). Components only display and call `selectOrganization`; all switching lives in the runtime store.
- Switching (from any entry point) clears projects and sessions, ignores late responses from the previous organization, and takes an open canvas or session view home. Running agents keep running while hidden. Switching back reopens that organization's last canvas if it still exists there.
- Adding a repository that already exists in another organization shows a toast (15 s) with "Switch to <organization>" and "Move here". Each acts once and closes the toast; the dialog that started the clone shows the error.
- Personal organization settings hide invite, transfer, leave, delete and the URL name (one line explains that it has none), and explain that its projects belong to the user alone. Its name and image are editable; it is labelled by its name ("Personal" until renamed).
- Settings > Organization > Identity edits the active organization. Owners and admins (and the owner of Personal) can change the name (saved on blur or Enter), the image and, for team organizations, the URL name. Members see the same fields read-only, with no Save or upload controls.
- Image: choose, drop or paste. The client centre-crops to a square, resizes to 256 px and uploads WebP (PNG when WebP is unavailable) at once, showing the new image while it uploads; a failed upload toasts and keeps the old image. Remove returns to the initials. The image replaces the initials everywhere they appear (switcher trigger and list, account menu, settings); until it loads, or if it fails, the initials show.
- URL name: lowercase, shown with a full URL preview. Typing is checked after 300 ms against `slug-available` with inline states: checking, available, taken, reserved, invalid (invalid is judged locally, with no request). Save is enabled only for "available" (or "could not check": the server re-checks) and is disabled for the unchanged value. A 409 on save flips the field to "taken". Changing it breaks nothing keyed by URL name (projects, invitations and the `X-Floq-Organization` header use the id); old-URL redirects do not exist.

## Scope boundary

Visual changes must not alter provider authentication, runtime request/response shapes, session creation semantics, terminal mounting, or server lifecycle. New navigation and screen-specific interaction owners require an explicit contract update before implementation.

Plugins must not alter provider authentication, session creation, terminal mounting, server lifecycle or core request shapes. New plugin contribution points require a contract update.
