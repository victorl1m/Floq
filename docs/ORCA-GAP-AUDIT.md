# Floq vs. Orca: capability gap audit

**Purpose:** identify Orca capabilities that would materially improve Floq, based on Orca's official product/docs and the Floq checkout inspected on 2026-11-01. This is a prioritization document, not a feature promise.

**UX constraint:** keep Floq's existing layout, visual language, dialogs, navigation, and interaction patterns. Use Orca only as a capability reference. Prefer reliability and backend work; add controls inside existing Floq surfaces where needed. No wholesale redesign.

## Scope and evidence

- Orca means the coding-agent IDE at [onorca.dev](https://www.onorca.dev/), not the unrelated Orca screen reader or security products.
- Orca evidence is its [official overview](https://www.onorca.dev/docs), [worktree guide](https://www.onorca.dev/docs/model/worktrees), [first-session guide](https://www.onorca.dev/docs/first-session), [agent/session guide](https://www.onorca.dev/docs/model/agents-sessions), and [official homepage](https://www.onorca.dev/). Its installed local CLI is v1.4.225 and running (`orca status --json`); `orca --help` exposes worktree, terminal, file, agent, and orchestration command families. The app feature list below follows official documentation; local CLI presence corroborates that it is the relevant Orca build.
- Floq evidence comes from this source checkout: `src/components/agents/new-agent-dialog.tsx`, `src/components/agents/terminal-panel.tsx`, `src/components/agents/session-terminal.tsx`, `src/components/home/home-view.tsx`, `src/components/home/clone-dialog.tsx`, `src/components/sidebar/project-list.tsx`, `src/lib/runtime/client.ts`, `src/lib/runtime/projects.ts`, `runtime/src/manager.ts`, `runtime/src/server.ts`, `runtime/src/orchestrator.ts`, `runtime/src/vault.ts`, `runtime/README.md`, `docs/ORCHESTRATION.md`, and `DESIGN.md`.
- This is a source and public-doc comparison, not a runtime test of every Floq flow or a full reverse engineering of Orca. A feature not located in the Floq source scan is marked “not found in inspected source,” not treated as proof no prototype exists.

## Floq strengths to preserve

- Cloud sessions run in per-user encrypted shards, with durable session state and sleep/resume. Orca is primarily a local agent development environment; these models solve different problems.
- Floq has authenticated, per-user provider/Git credentials and a vault, plus server-side orchestration and bounded inter-agent collaboration (`runtime/src/vault.ts`, `runtime/src/orchestrator.ts`, `docs/ORCHESTRATION.md`). Orca's IDE workflow is not a substitute for those cloud/control-plane features.
- Floq already has provider usage, skills settings, GitHub repo clone/search, model selection, project/session grouping, terminal replay, and interactive shell sessions. Do not list these as missing just because Orca also has them.

## Existing fixes: not product gaps

The current task brief identifies in-flight local fixes for dynamic Codex app-server model discovery, no-daemon/process cleanup, timeout/idempotency handling, and project `gitUrl` metadata. Keep these scoped reliability fixes moving; they are not Orca parity features. Confirm their landed state before opening duplicates.

## Suggested order from the baseline audit

1. Finish and verify the already-authorized reliability fixes above.
2. Verify the same-checkout concurrency behavior, then design a guarded worktree-backed workspace option if the risk is confirmed.
3. Add read-only diff review as the first contained Orca-inspired capability.
4. Add terminal scrollback search/splits and small at-a-glance status improvements as capacity allows.
5. Reassess broad integrations only after the core multi-session workflow is safe and reviewable.

Nothing in this audit authorizes deleting workspaces, silently changing existing project paths, enabling unattended provider permissions, or publishing code externally.

## Implemented in the current checkout

- **Read-only project review:** the session Changes dialog lists changed paths and displays unified diffs through authenticated, per-user runtime routes. The Git reader constrains worktree/git metadata to the user's shard, runs read-only commands with an allowlisted environment, disables hooks/fsmonitor/external diff and text conversion, caps output/time, and never logs patch content. It does not commit or publish code.
- **Terminal search and comparison:** terminal scrollback search uses the existing xterm instance; Enter/Shift+Enter move between hits, missing text is reported, and closing search restores terminal focus. Split view reuses opened sessions and shows two selected panes while keeping each session mounted once. Agent/shell tabs can coexist in the Terminal area; agent tab close is local and does not delete the session.
- **Canonical project workflow:** a per-user project/workspace registry backs the sidebar, Home project selector, and New Agent dialog. Repository import waits for the clone and adds the canonical project immediately. New prompts and agent/terminal sessions select a registered project/workspace; the Home picker no longer offers a personal-folder or pending-clone choice. Project marks, names, branch/worktree labels, and session status reuse the existing compact sidebar/titlebar surfaces.
- **Rollout status:** these registry and project-scoped creation changes are implemented in the current checkout; deployment and final integrated validation are pending.
- **Reliability and access controls:** project/session APIs enforce user ownership; session creation references project/workspace IDs rather than accepting arbitrary absolute project paths. Closing an agent tab hides it locally; it does not delete the underlying session.
- **Visual constraints:** these additions use the existing Floq dialogs, titlebar, tab strip, dropdowns, semantic CSS tokens, and project/sidebar identity component. The Orca comparison informed capability selection only; it did not replace Floq navigation or visual styling.
