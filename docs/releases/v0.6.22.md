# Floq v0.6.22

## Changes

- **Agent memory (opt-in).** Agents can store and search durable project memories on a Redis 8+ or DragonflyDB server.
  - **Search:** full-text and semantic, ranked by meaning. An exact identifier match gets a boost.
  - **Embeddings:** run locally by default with IBM Granite 311M multilingual; e5-small and OpenAI are alternatives.
  - **Imports:** existing "memory" notes are imported the first time memory starts.
  - **In the app:** the canvas has a new Memory dialog, opened from the titlebar.
  - **Off by default:** memory stays off until you configure it (see Upgrade notes).
- **Permission prompts on the island.** Claude Code still asks for some actions even with automatic approval on, such as the "Dangerous rm operation" safety check. Floq now shows these on the island as an approval instead of leaving them in the terminal, where Claude blocked them after about 45 seconds.
  - **No answer:** after 40 seconds the action is denied.
  - **Runtime unreachable:** the normal terminal prompt is used.
  - Floq never allows an action on its own.
- **Plugins in other channels.** Plugins can relay pending questions and approvals to other channels with `ctx.attention`; the WAHA plugin uses it for a WhatsApp fallback. A plugin can never allow an irreversible approval.
- **Plugins screen.**
  - The catalog dialog has a fixed size, with the filters, cards and details scrolling inside it.
  - Cards are the same size and show Installed, Update available, Built in and On.
  - Loading, error and empty states appear inside the dialog.
  - Install from GitHub is in the sidebar.
  - Settings > Plugins rows are steadier.
- **Island recovery.** The island no longer stays invisible after being hidden for hours. Windows no longer throttles its window. If the island does not render within 1.5 s of being shown, it is reloaded, and if that fails it is recreated and the pending request is shown again. Each step is written to `island.log`.
- **Tasks.** The "No boards yet" box no longer has a translucent fill.
- **Sidebar.** A new subfolder inside a nested folder keeps the nesting of its siblings.

## Upgrade notes

- **Rebuild and redeploy the runtime image.** The permission hook and the memory runtime live in the image.
- **Enabling agent memory.** Memory is off while `FLOQ_REDIS_URL` is empty. To turn it on with the bundled DragonflyDB, set these in Dokploy > Environment, then redeploy:
  - `COMPOSE_PROFILES=memory`
  - `FLOQ_REDIS_PASSWORD` (a long random value; the store refuses to start without it)
  - `FLOQ_REDIS_URL=redis://:<same password>@dragonfly:6379`

  For Redis instead, use the `memory-redis` profile. Full steps are in `runtime/.env.example` and `runtime/README.md`.
- **First local search.** The first local-embedding search downloads the Granite model (about 347 MB) and adds about 620 MB of RAM. Use `FLOQ_EMBEDDINGS=off` below about 4 GB of RAM.

## Verification and known limits

- **Builds:** the frontend build and the runtime typecheck pass.
- **Frontend tests:** 171/172 pass. The one failure is the unchanged malformed navigation-map preference test.
- **Runtime tests:** with the sandbox PTY stub, 838 pass, with 10 known port-request cancellations and 1 skip. The 1 failure is a sandbox test that needs a real PTY.
- **Memory:** the memory tests pass against a real Redis 8.4 and against Dragonfly.
- **Not verified:**
  - **Compose memory profiles:** not run with Docker. The pinned Dragonfly image tag `v2.1.0` exists in the registry.
  - **Live Granite download:** not tested inside the runtime.
  - **Island recovery:** the Rust is only compiled by the Windows CI build; reloading a frozen island was not tested on Windows.
  - **Permission hook:** not checked against a live "Dangerous rm" prompt. The Claude Code docs and the bundled Claude 2.1.319 support it.

This is a pre-release.
