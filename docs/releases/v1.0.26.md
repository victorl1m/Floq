# Release v1.0.26

## Changes

- **Update runtime updates itself in Docker, with no platform setup.** Clicking Settings › Runtime › Updates › Update runtime starts a short-lived helper container from the runtime image. It clones the newest release tag, rebuilds the runtime image under the same name, and swaps the runtime container in place with its exact config (environment, volumes, networks, labels). If the new container does not start, the old one is put back.
- The Dokploy-specific variables from v1.0.25 are removed; nothing needs to be configured.
- `docker-compose.yml` mounts the Docker socket at `/run/floq-docker.sock`. Agent sandboxes replace `/run` with an empty tmpfs and the socket is root-only on the host, so agents cannot reach it. Remove that volume line to turn in-app runtime updates off.
- The runtime update check now sees Floq's releases (they are published as pre-releases, which GitHub's "latest release" endpoint skipped).

## Deployment

Redeploy the runtime once with this compose file (it adds the socket mount). From then on, Update runtime in Floq does it.

## Tests

- Runtime build; adminUpdates (8). The Docker swap itself is untested here (no Docker daemon in the build sandbox).
