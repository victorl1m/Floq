# Release v1.0.25

## Features

- **"Update runtime" works on Dokploy.** Set `FLOQ_DOKPLOY_URL` (usually `http://dokploy:3000` from inside Dokploy's network), `FLOQ_DOKPLOY_API_KEY` and `FLOQ_DOKPLOY_COMPOSE_ID` on the runtime's compose service, redeploy once, and Settings › Runtime › Updates › Update runtime asks Dokploy to redeploy the compose (pull, rebuild, restart). The API key is read from the environment by the deploy step only, never placed in argv, logs or the update output.
- `docker-compose.yml` now passes `FLOQ_UPDATE_RUNTIME_COMMAND` through (it was silently dropped before), plus the three Dokploy variables.

## Tests

- Runtime: adminUpdates (8, new Dokploy config validation and plan), and an end-to-end check of the deploy step against a fake Dokploy (correct `POST /api/compose.deploy`, compose id, key header, key absent from output).

## Deployment

Set the three Dokploy variables in Dokploy › the runtime compose › Environment, then deploy this version manually once; from then on "Update runtime" in Floq redeploys it.
