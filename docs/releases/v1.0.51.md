# Release v1.0.51

## New

- **The built-in WhatsApp server runs by default, with no setup.** WAHA is now a regular service in the runtime's `docker-compose.yml` (its own container, same compose, no profile). The runtime creates a random API key once in a small volume shared only with WAHA, and WAHA starts with it. Deploy or update the runtime, open Settings > Integrations > WhatsApp and scan the QR code. Your own key still works (`FLOQ_WHATSAPP_API_KEY`); `FLOQ_WHATSAPP_BUILTIN=0` turns the built-in server off.

## Tests

- Runtime: zero-config key (created once, reused, own key overrides, off without a file), compose shape (no profile, key from the shared volume, no host port), WhatsApp server routes; Playwright Integrations (11); frontend typecheck.

## Deployment

Runtime change: redeploy the runtime with the updated compose file (Dokploy does this on push). The first start pulls the WAHA image.
