# Release v1.0.10

## New: browse from your own connection (desktop app, off by default)

The agent browser runs on the server, so sites see the server's IP address and location. With this setting on, all of its network traffic leaves from your computer instead, through the Floq desktop app, and sites see your IP and location.

- **Where.** Settings > Agents, "Route browser traffic through this computer" (off by default). When it is on you choose what happens if the computer is offline: *Pause the browser* (default) or *Use the server's connection*. There is also a daily data cap and an "Allow other ports" option. The setting is per user and per machine, and only the desktop app can relay.
- **How it works.** Chromium on the server sends everything to a local SOCKS5 listener in the browser daemon. The daemon forwards it over one binary channel to the runtime, which relays frames over a WebSocket that the desktop app dials out (so it works behind NAT). The desktop resolves the names and opens the real connections. The runtime never opens target sockets. Chromium runs with QUIC off, WebRTC limited to proxied UDP and no local DNS.
- **Guard in the desktop app.** Only ports 80, 443, 8080 and 8443. Loopback, private, link-local and every on-link prefix of your computer (IPv4 and IPv6), your default gateway and your own public IP are refused after DNS, and the connection goes to the address that was checked. Connection and byte caps apply. A local log keeps the last 500 connections and never leaves your computer. The tray menu has "Stop using my connection".
- **Fails closed.** With *Pause the browser*, if the desktop is not connected the browser does not fall back to the server. The Browser node shows "Paused" with a **Use server connection this time** button. That choice is temporary and in memory: your saved mode is untouched and it ends when your computer comes back, when you change the mode, or when the browser goes idle. A badge on the node shows which connection is in use.
- **Limits.** It changes the IP and location only. No stealth: no user-agent, webdriver or fingerprint changes, so sites can still detect and block an automated browser. The browser's timezone and locale stay the server's, and a site may notice that they do not match your IP.
- **Review.** Reviewed by Opus; all findings are fixed, including an interop test between the runtime hub and the real daemon codec.

## Fixes in the browser node

- **Popups.** `target=_blank` links and `window.open` used to leave a blank popup at an empty URL. The node's page now goes to the popup's URL and the popup is closed. `window.opener` is lost.
- **JS dialogs.** alert, confirm and prompt show over the page in the node and your answer goes back to the page. A dialog that is still open when you reopen the node is shown again. `beforeunload` is accepted automatically.
- **Clipboard shortcuts.** Ctrl/Cmd+A, C, X, Z and Y work in the page. Copy and cut put the selection on your own clipboard.
- **Downloads.** The node shows when a download starts, finishes or fails. Files land in `~/Downloads` in the sandbox.
- **Crash recovery.** If a page's renderer crashes, the node reopens at its last URL.
- **Saved sessions.** Session cookies and each node's last URL survive the browser's idle shutdown (`session-state.json`, mode 0600, in your encrypted home).
- **Clearer sandbox message.** `floq browser status` shows one line when Chromium cannot start its own sandbox, not a crash trace.

**Not fixed:** a page's file upload dialog (your files are not in the sandbox, so uploads only work through an agent with `browser_file_upload`). Daemon stdout EPIPE after the runtime pipe closes is unguarded; the daemon exits, which is the intended shutdown.

## Chromium sandbox stays off

Chromium still runs with `--no-sandbox`, inside the agent sandbox. Its own sandbox needs `unshare(CLONE_NEWUSER)` plus a write to `/proc/self/uid_map`, and the host refuses that write (`kernel.apparmor_restrict_unprivileged_userns=1`, no capabilities, `NoNewPrivs`). The setuid helper cannot work under `--no-new-privs` either. Details and the options considered are in `docs/design/agent-browser.md`.
