# Release v1.0.7

## Features

- **Claude usage fallback chain.** When a Claude agent hits its plan usage limit, Floq steps down a chain you set in Settings > Agents instead of leaving the agent stuck:
  1. **Lower Claude model** (Fable, Opus, Sonnet, Haiku). On by default.
  2. **Another Claude account** you connected under Settings > Accounts. Off by default.
  3. **Codex**, with a handoff file that carries the task, recent prompts, todos and the git state. Off by default.

  When the limit window resets, agents swap back on their own (on by default). A badge on the agent card shows the fallback and lets you return now, keep it, or pick a per-agent policy (default, model only, pause). `floq recruit` and `floq subagent recruit` take `--fallback default|model|pause`. Extra Claude logins are stored as reserve accounts; the active one stays where it was, so refresh and usage are unchanged.

  **Caveat:** the 5-hour and weekly limits apply to the whole account, so a lower model does not help against them. With the default chain (model step only), a 5-hour or overall weekly limit pauses the agent until the reset. Turn on the account or Codex step to keep working through those. Only model-specific windows, such as Opus weekly, are solved by the model step.
- **Agent browser.** One shared headless Chromium per user runs inside the user's sandbox and is available to Claude and Codex agents as the MCP server `floq-browser` (Playwright MCP). A **Browser** node on the canvas (right-click > Open browser) streams it live, so you can watch and log in once for every project. Settings > Agents > Browser has the on/off toggle, status, restart and clear-data controls. `floq browser status|version|restart` works from an agent terminal.
- **Cookie and bookmark import.** Import a Netscape `cookies.txt`, a JSON cookie export or a bookmarks HTML file into the browser profile. Preview the sites first, pick which to import, and remove a site's cookies later. Bookmarks are stored but nothing reads them yet.
- **claude.ai connectors.** A per-user toggle (default on) for loading your claude.ai connectors in Claude sessions, with a read-only list of connected connectors. Off writes `disableClaudeAiConnectors` into the managed settings. It applies to new or restarted sessions.

## Not built

Fallback:

- `Undo` on the swap toast.
- Detecting Codex's own usage limit (Codex as the origin of a fallback).
- Handoff pruning on session delete (files older than 7 days are pruned on every write).
- Passing `--fallback` into create (it is applied right after recruit).
- A Connect link next to an unavailable step (an inline note says what is missing).

Browser:

- Nothing reads the imported bookmarks yet.
- Per-project browser profiles (all agents of a user share one profile and one set of logins).
- Session cookies do not survive a browser stop or restart.

## Runtime image

The runtime image gains a pinned `chromium-headless-shell` and `@playwright/mcp` in a new `browser` build stage, plus the shared libraries and fonts Chromium needs. The design estimates **about 400 MB uncompressed** (roughly 150 MB compressed in the registry). The stage, the library list, the bookworm package names and the migrations were checked by a dry run; the image was not built with Docker here, so measure the real size on the first build.

- Dokploy redeploys the runtime on push to main, so the larger image ships with this release. The migrations (`usage_fallback`, `fallback_*`, `claude_accounts`, `claude_ai_connectors`, `agent_browser`) run on startup and only add columns and a table.
- To build without the browser: `docker build --build-arg FLOQ_BROWSER=0 runtime`. The server then reports the browser as missing and the settings show it as not installed.
- `FLOQ_AGENT_BROWSER=on|off`, `FLOQ_BROWSER_IDLE_MS`, `FLOQ_BROWSER_MEM_MB` and `FLOQ_BROWSER_ALLOW_PRIVATE` are documented in `docs/runtime-agents.md`. Without `FLOQ_NETNS=required`, the browser blocks loopback and private addresses with a CDP interceptor; see `SECURITY.md`.
