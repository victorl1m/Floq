# Release v1.0.37

## Browser: CAPTCHAs you solve yourself should pass

Research (`browser-captcha-research.md`) found the human click itself is fine; the browser was announcing itself as a server-side automated browser. This release removes most of those signals:

- **Real browser window on a virtual display.** Chromium runs headful on a per-user Xvfb display (added to the runtime image) instead of `--headless=new`, so it no longer reports "HeadlessChrome". If Xvfb is missing or fails it falls back to headless.
- **Your screen, pointer, timezone and language.** The desktop app reports them when it opens a Browser node and the browser starts with them (measured: 2560x1440 screen, fine pointer with hover, America/Sao_Paulo, pt-BR instead of 800x600, no pointer, UTC, en-US). Applied at the next browser start.
- **Challenge frames are left alone.** Cloudflare Turnstile, reCAPTCHA and hCaptcha frames are no longer paused, intercepted or probed on mouse moves.
- **Stable sessions.** Egress never switches mid-page-load or within 15 s of your input (deferred at most 90 s), and session cookies are saved every 5 s so they survive a browser restart.

Not changed: `navigator.webdriver` stays true until you decide (decision pending).

## Tests

- Runtime build, root typecheck, browser tests (110 of 112; the 2 others need the native terminal module, missing in the build sandbox). New tests: Xvfb on/missing/failing fallback, client environment sanitising and flags, challenge URL matcher, egress busy deferral.
- Not tested: real headful run on Xvfb, real Turnstile / reCAPTCHA / hCaptcha widgets.
